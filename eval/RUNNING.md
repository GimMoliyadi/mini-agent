# 运行与解释 Eval

使用项目虚拟环境：

```powershell
.venv\Scripts\python.exe -u eval\run_eval.py eval\tasks.json
```

每题复制工作目录到独立临时目录，子进程通过 `AGENT_WORKSPACE` 指向该目录。
原工作目录不会被清空或覆盖。旧 `.workspace_snapshot` 不再参与新运行，无需删除。

每完成一题，结果原子写入 `eval/runs/<时间戳>/results.json`。
`status=running` 表示运行尚未完整结束；`planned_tasks` 是计划题数。
完整结束后才更新 `eval/results.json`，任何失败使命令退出码为 1。
中断前已完成题目的记录保留；正在执行的题目还没有完整记录。
写文件任务的 `output_content` 保留实际产物供人工复核。

规则通过不等于人工验收：摘要是否忠实、比较是否正确仍需复核。
列目录同时检查遗漏和虚构；原样写入按完整文本比较。
配置错误、Provider 错误、执行器崩溃分别统计。
子进程 900 秒超时会记录失败并继续下一题。

连接说明：SOCKS 代理需要 `socksio`，本机代理端口也必须实际监听。
TCP 建连成功不能证明模型请求成功，单次短探测也不能推断所有任务耗时。
运行时网络环境应显式配置；不要把代理故障解释成 Agent 能力失败。

后续可用性验收顺序：

1. 完成本轮真实评测并逐题人工复核，保留产物和失败原因。
2. 增加单任务 CLI、明确退出状态、取消处理和会话保存/恢复。
3. 完善长文件分段读取与历史重读，验证上下文压缩后的信息完整性。
4. 增加写前确认/只读模式、原子写入和变更证据。
5. 扩充跨轮、长文件、错误恢复评测，再验收真实日常任务。

当前定位是本地文件学习助手；上述验收完成前，不宣称通用 Agent 已完整可用。
