# 发布评测规范

## 当前状态

`release_tasks.json` 是代表性自然任务的**评测规范**，不是已有 `run_eval.py` 的任务输入，也没有新增真实模型执行器。本轮没有调用真实模型，没有模型通过率、质量分、平均成本或跨平台成功数字。历史 `eval/` 报告只适用于其中记录的版本、任务、样本和配置，不能替代本规范的验证。

离线回归检查协议、权限、文件边界、验收与预算等确定性行为；它不能证明自然语言任务质量。真实模型评测必须由用户明确指定模型、允许发送的数据、预算和开跑范围后，单独启动。安装或 CI 不自动执行真实评测。

## 第一关：离线工程校验

从源码根目录、使用已安装锁定依赖的 Python 3.11 虚拟环境运行：

```powershell
.\.venv\Scripts\python.exe scripts/check.py
.\.venv\Scripts\python.exe scripts/check.py --packaging-only
```

Linux 对应解释器为 `.venv/bin/python`。默认入口会创建独立临时副本，不复制 `.env`、实际会话、Git、Serena、虚拟环境、状态日志或外部链接。测试的临时目录、工作区、状态目录及用户配置目录均指向副本，模型环境为 dummy + 回环地址，真实 Key 与代理不继承；`GIT_CEILING_DIRECTORIES` 防止 Git 上溯原仓库。

行为入口必须实际运行全部 `unittest tests`、两个历史脚本测试、metrics 脚本、五项 eval 可靠性测试和 Python 语法检查。任何检查失败都必须返回非零，不能减少测试、跳过失败或换成弱断言。打包入口另外检查扁平模块清单、锁定版本与离线依赖闭包，构建 sdist/wheel、离线安装 wheel，并从无源码遮蔽的目录执行已安装的 `mini-agent --help`。

Windows 为兼容源码启动器测试，会在副本中临时建立指向已有 `.venv` 的目录链接。清理必须先使用仅删除链接的操作移除它，绝不递归删除目标虚拟环境。Linux 使用目录符号链接，原则相同。

本轮为项目虚拟环境补齐了 `wheel 0.48.0` 及其构建依赖，并使用现有 setuptools 完成本机构建检查。离线入口直接调用 setuptools 后端，不需要 build 前端；检查本身不会联网下载缺失依赖。安装验证使用真实 wheel，检查安装后的帮助、版本查询和会话列表，不用空 wheel 或源码导入替代。CI 的安装阶段准备构建工具，之后的检查离线；其 Windows/Linux 配置不等于已经在远程 CI 或 Linux 上实跑。

## 第二关：真实模型开跑前确认

开跑前应明确确认以下内容：

1. Provider 地址与模型、模型服务商的数据处理范围，以及 fixture 是否允许外发。
2. 一个任务最多的时间、模型调用、工具调用、输出 token 与累计 token 额度。
3. `usage` 缺失时选择 STOP 还是估算；估算不等同于精确计费限额。
4. 每题重复次数、交互审批方式和中途取消的人工操作计划。
5. 使用全新临时工作区与独立状态目录；不得指向真实桌面、demo 或实际会话。

默认计划是每项任务独立重复三次。计划重复数不是实际样本数；失败、取消、Provider 故障和无效测试仍须保存证据，不能悄悄补跑后删掉原结果。

## 第三关：fixture 与判据

每题的 `fixtures` 是相对路径到 UTF-8 文本的映射，写出时必须保留 JSON 字符串中的换行字节；`fixture_recipe` 用于可复现生成长文件。对带 `contract` 的任务，将 `task_id`、`instruction` 与 contract 字段组成独立 Coding Contract；测试文件固定且受保护，Agent 只允许修改 `allowed_paths`。

自动判据逐项执行，不能只检查文件存在或退出码为零：

- 完整内容使用 JSON 结构相等或 UTF-8 字节相等；检查输入文件是否保持原样。
- Coding 任务独立重跑固定测试，并验证实际测试数量非零、没有失败/错误/跳过。
- 核对最终文件差异、finish 状态与独立 Acceptance；普通最终文本不是 Coding 验收。
- 审批拒绝必须没有副作用；零测试场景应被拒绝验收，这是该场景的正确结果。
- 取消/恢复/撤销需要人工步骤与机器结果一起核验，不强行套成单轮成功率。

每题的 `manual_criteria` 由人对照来源和原始结果逐项标为“通过 / 失败 / 未评”。机器判定不替代真实性、完整性、冲突处理或表达质量的复核，不增加 LLM judge。

## 证据与统计

逐题逐次保留 `record_fields`，包括源码版本、平台、SDK、模型、脱敏配置、审批、工具轨迹、文件差异、独立最终测试数量、结束原因和人工结论。`usage_known`、`usage_missing`、`usage_estimated` 分开记录，未知值不得填零后参与成本平均。

原始结果放在显式指定的私有状态目录或 `eval/release-runs/`（已忽略），不将真实 Key、完整请求头、实际会话或用户文件提交到 Git。报告同时列出全部尝试数、有效模型样本数、Provider 失败数、取消数和未评数，说明每个指标的分母；三次小样本不足以宣称稳定性或泛化通过率。

## 发布判断

只有离线工程检查全部通过、目标平台实际运行过、真实评测及人工判据有可追溯证据、未解决问题有明确边界说明，才能讨论发布。包元数据只是本地安装能力，不意味着已经发布。仓库尚未指定许可证；向其他人分发或发布包之前，必须由权利人决定许可证与授权范围。
