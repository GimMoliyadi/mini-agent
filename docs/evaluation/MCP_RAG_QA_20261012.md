## 修复与技术决策

- MCP 关闭时取消并等待后台任务完成清理，修复直接停循环造成的遗留任务。
  启动清除旧的 readiness 状态，重复进入活动 bridge 明确报错。
- MCP 保留上游 JSON Schema 和结构化 artifact；文本块直接合并，避免把无意义的
  内容块 ID 发送给模型。服务器错误提供可恢复信息，超时独立标记；不自动重放。
- 凭据按 artifact 结构脱敏，避免先对 JSON 字符串脱敏破坏结构；RAG 文本和来源
  先脱敏再截断，防止只留下已知凭据的部分前缀。
- RAG 按真实 API 保留 rank、score、title、file_path、heading、source、chunk_index。
  无效原文返回结构化错误；空结果不编造知识。NaN/Inf 超时和分数得到明确处理。
- Settings 修复相对 MCP 配置路径解析，拒绝非有限超时；checkpoint 拒绝符号链接
  和 Windows junction/reparse point，避免状态目录逃逸。
- 失败 ToolMessage 中的“测试通过”文本不再能成为验收证据。
- 每个事件标记 task_id，交错运行/恢复不同会话不会混入其他任务的 trace。
  模型事件在真实响应返回时记录，失败批次不会漏记，恢复验证节点不会重复计费。
- 单批工具的硬限制保留；将实际限制注入模型提示，修复实测中模型一次提交 9 个
  工具超过默认上限 8 的失败路径。
- 固定 MCP 可选依赖并纳入四平台 CI；生产依旧只有一个 `create_agent` 工具循环。

MCP 继续使用已验证的 `langchain-mcp-adapters 0.3.2` / SDK `1.30.0`。
旧 adapters 仓库已归档，官方 `langchain.mcp.MCPAdapter` 仍为 beta；本轮先完成
稳定版本回归，下一阶段建立等价用例后迁移，详见
[上游参考与决策](../framework-references.md)。

## MCP 真实服务

`tests/fixtures/mcp_server.py` 使用官方 Python SDK 启动独立服务，测试执行实际
stdio 子进程和 Streamable HTTP 网络请求；模型可以同步调用其上游异步工具。

覆盖：发现、显式工具允许列表、参数 schema、参数类型错误、结构化成功结果、
服务器 isError、超时发生在服务器工具执行期间、取消后再次调用、关闭与重启、
两服务器同名工具、只读免审批、ASK 跨应用批准恢复、DENY 拒绝、Contract 拒绝
未声明本地修改路径的外部副作用工具。未连接未知公网 MCP 服务。

默认上游工具每次调用建立独立远端会话；后台循环的生命周期不等于远端状态会话。
远端有副作用调用的 exactly-once 语义未实现。

## RAG-chain 真实应用、存储与 HTTP

上游源码固定到 rag-chain
`f6dd0b391aa25a2db121260a68b795ccf2dd0ff3`。
实际执行 `app.main:create_app`、上游 engine/retriever、ChromaStore、SQLite 数据仓库
和 FastAPI/Uvicorn 路由，没有复制生产 RAG 实现到 mini-agent。

独立环境版本：Chroma `1.5.9`、FastAPI `0.143.0`、Uvicorn `0.54.0`、
Pydantic `2.14.1`、httpx `0.28.1`。
索引为 2 篇 synthetic 文档、3 个 chunk/向量；前两项为 stable_unique 规范，
第三项为无关折扣说明。确定性 8 维词汇 embedding 替身避免下载模型和访问外部
嵌入服务；Chroma 和 SQL 都是真实持久化实例。

直接向量检索与 Retriever 均将两个规范片段排在前两位；无关文档不进入 top_k=2。
Chroma metadata → Retriever → SQL 文档回表正确，真实 HTTP `/health`、
`/api/documents`、`/api/search`、`/api/chat` 均返回 200。
`/api/chat` 只验证上游 MockLLM 的引用组装；mini-agent 实际仅调用 `/api/search`。
这证明接口、存储、检索和引用链路，不代表真实 embedding 模型的语义检索质量。

原始独立数据证据：[upstream-rag-20261012.json](upstream-rag-20261012.json)。
另外提供无需 Chroma 的 SQLite FTS5/BM25 HTTP fixture，供普通 CI 和演示使用。

## 复现

普通开发与独立 HTTP fixture 的运行方法见 [集成说明](../integrations.md)。
上游实际存储验证在独立 RAG 环境执行，避免与 mini-agent 的依赖混用：

```powershell
git clone https://github.com/GimMoliyadi/rag-chain .tmp/rag-chain
git -C .tmp/rag-chain checkout f6dd0b391aa25a2db121260a68b795ccf2dd0ff3
python -m venv .tmp/rag-env
.tmp/rag-env/Scripts/python.exe -m pip install chromadb==1.5.9 fastapi==0.143.0 uvicorn==0.54.0 httpx==0.28.1 python-dotenv==1.2.4
.tmp/rag-env/Scripts/python.exe examples/upstream_rag_http_acceptance.py --checkout .tmp/rag-chain --state .state/upstream-rag.json
.tmp/rag-env/Scripts/python.exe examples/upstream_rag_http_acceptance.py --checkout .tmp/rag-chain --serve --port 8766
```

另一终端：

```powershell
python examples/live_integration_acceptance.py --config-dir C:/private/model-state --rag-url http://127.0.0.1:8766 --only rag-mcp-local-development --output .state/upstream-live-integrations.json
```

按本机需求配置代理；loopback 地址加入 NO_PROXY。Linux 使用对应的 `bin/python`。
服务和索引只使用脚本自建临时目录；退出后可以清理，不需要私人知识库。
