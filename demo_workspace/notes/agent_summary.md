# Agent 学习摘要

来源：`agent_notes.md`

## 1. Agent vs 普通聊天机器人

- 聊天机器人：一问一答，只会"说"。
- Agent：自主判断下一步，动手做，看结果，再继续做，直到任务完成。
- 关键差别不在模型大小，而在有没有「工具」和「循环」。

## 2. Agent 循环

```
任务 → LLM 判断下一步 → 调用工具 → 得到结果 → 再交给 LLM → ... → 完成
```

- 工具的结果必须**回喂**给 LLM，LLM 才可能改变下一步决定。
- 只调用一次工具、把结果直接打印出来，那只是"带函数调用的聊天"，还不是 Agent。

## 3. 工具是什么

- 工具就是 Agent 能调用的普通函数（读文件、写文件、列目录、算数等）。
- 工具本身很笨：只执行，不做判断。
- 聪明的是 LLM：决定**什么时候**用哪个工具、**传什么参数**。
- 写工具的原则：
  - 参数尽量简单；
  - 错误信息尽量明确——LLM 凭返回内容决定下一步，报错含糊会让 Agent 乱猜。

## 4. 本项目的约定

- **安全边界**：Agent 只能碰 `demo_workspace/` 里的文件，不许碰项目外的东西。
  这是必须在代码层面真正拦截的硬边界，不是写在文档里的愿望。
- **工程节奏**：每加一个能力，都必须先跑通再往下走。

## 5. 一句话总结

Agent 的本质是「LLM 决策 + 工具执行 + 结果回喂」的闭环；工具要简单可靠、报错要清晰、安全边界要在代码里真正落地。
