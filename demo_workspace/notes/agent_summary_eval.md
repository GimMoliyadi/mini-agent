# Agent 学习摘要

来源：`agent_notes.md`

## 核心区别：聊天机器人 vs Agent

- **聊天机器人**：一问一答，只说不动手。
- **Agent**：自主决定、动手执行、观察结果、迭代推进直到完成。

关键差别不在模型大小，而在是否具备「**工具**」与「**循环**」。

## Agent 循环结构

```
任务 → LLM 判断下一步 → 调用工具 → 得到结果 → 再交给 LLM → …… → 完成
```

要点：工具结果必须**回喂**给 LLM，LLM 才能据此调整下一步。
若只调用一次工具就直接输出结果，那只是"带函数调用的聊天"，并非真正的 Agent。

## 工具的定位

- 工具 = Agent 可调用的普通函数（读/写文件、列目录、算数等）。
- 工具本身"笨"：只执行，不做判断。
- 判断由 LLM 负责：决定**何时**用哪个工具、**传什么参数**。
- 因此工具设计原则：**参数尽量简单，错误信息尽量明确**——
  错误信息含糊会让 LLM 猜错下一步。

## 本项目约定

- Agent 只允许访问 `demo_workspace/` 内的文件，越界必须在代码层真正拦截，
  不能仅靠文档声明。
- 每新增一项能力，都要先跑通再继续开发。

## 一句话总结

Agent = LLM（大脑） + 工具（手脚） + 循环（反馈），三者缺一不可。
